Configuration is split between Discord server settings and deployment settings.

## Discord server configuration

Each server has an independent `guild_config` row. Use `/config show` to display leaderboard, active-lobby, guide-forum, role, rank cooldown, command-channel, and debug-export settings. Public channel rules apply to `/rank`: a block denies the channel; any live allow rule changes the default to deny. Threads inherit their parent channel. Cooldowns are in memory and reset with the process.

## Guide forum posts

Guide posts reconcile every five minutes and immediately after `/refresh`, guide configuration changes, or a raw message deletion. Choose a forum channel where the bot has View Channel, Send Messages, Read Message History, Manage Threads, and permission to mention the selected role. Source Markdown cannot create mentions; creation posts use restricted allowed mentions for only the selected safe role.

Changing forums archives old managed posts and publishes replacements in the new forum. Missing posts are recreated. Website removals archive posts by default; automatic deletion is opt-in. Reset always archives.

## Required runtime settings

The bot requires `DATABASE_URL`, `DISCORD_TOKEN`, `SUPABASE_URL`, `SUPABASE_API_KEY`, and `BATTLEVIVE_URL`. `DISCORD_COMMAND_GUILD_ID` is optional. Leave it blank in production for global command registration; use a positive guild snowflake during development.

`DATABASE_URL`, `DISCORD_TOKEN`, `SUPABASE_API_KEY`, `BOOTSTRAP_JWT`, and `BOOTSTRAP_REFRESH_TOKEN` also support a corresponding `*_FILE` variable. The file form takes precedence, but defining both forms is a configuration error and stops startup. Secret files must contain a non-empty value and should be readable only by the runtime identity.

`SUPABASE_URL` must use HTTPS without embedded credentials. `BATTLEVIVE_URL` must use HTTPS and contain no credentials, query, or fragment.

## Battlevive token persistence

`BATTLEVIVE_TOKEN_STORE` accepts:

- `file` (default): use `BATTLEVIVE_TOKEN_PATH`, preserving local and non-AWS behavior. The running local bot owns and rotates `app/data/bot/battlevive_tokens.json`, which is its dedicated Compose bot-data mount;
- `ssm`: require `BATTLEVIVE_TOKEN_SSM_PARAMETER` and `AWS_REGION` and store the access/refresh pair as one JSON SecureString through the instance role.

An SSM write is attempted three times. A final failure degrades health and produces a critical log without exposing token values.

For a local source build, keep settings in `utils/.env` and start the base and
development override together. `utils/init.sh` obtains the bootstrap pair and
writes it there; do not paste generated token values manually. The rootless
Podman development override gives the persistent bot-data mount to the
container's fixed non-root UID so token refreshes remain writable.

## AWS production values

Static secrets use `/battlevive/production/secrets/...`; non-secret configuration uses `/battlevive/production/config/...`; rotating tokens use `/battlevive/production/tokens`; atomic non-secret deployment state uses `/battlevive/production/deployment/state`.

Secret values are entered interactively and are not Terraform inputs or state. At boot, the instance role renders them atomically below root:10001 mode-`0750` `/run/battlevive`. Each secret file, including `postgres-password`, is root:10001 mode `0640`: the fixed UID/GID 10001 runtime can read it but cannot replace it, and other users cannot read it. PostgreSQL consumes the password through `POSTGRES_PASSWORD_FILE`; the value must not be duplicated in Compose, command arguments, logs, or documentation.

Root-only mode-`0600` `/run/battlevive/host.env` contains no secrets. It supplies the AWS region, operations bucket, application log group, `/opt/battlevive` deployment root, and isolated `/var/lib/battlevive/{bot,postgresql}` paths. AWS production does not use a `.env` file.

Use `infra/tools/migrate-secrets.sh` for the interactive migration. Never paste secret values into an SSM command, shell history, Terraform variable, GitHub variable, or issue.
